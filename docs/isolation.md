# Isolation
<!-- summary: What a pane may read, write and reach, per pane, tab or space. -->

A pane starts with your access: its program, an agent included, can read and write your files and reach the network. **Isolation…** in a pane's menu narrows that. **Isolation for new panes…** in a tab's or a space's menu sets it for the panes opened there, and a split keeps the isolation of the pane it came from. A change applies when the program starts: **[r] save and restart the program** restarts it.

| Files | What the pane's programs get |
|---|---|
| Everything | Your files, as you. |
| This folder only | Write access to the pane's folder, temporary folders, `~/Library/Caches` and the agents' session folders. Its `TMPDIR` is a temp folder of its own, removed when its program ends. No read access to `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.netrc`, `~/.docker`, `~/.kube`, `~/.azure`, `~/.config/gh`, `~/.config/gcloud`, `~/Library/Mail`, `~/Library/Messages`, `~/Library/Cookies` or nerd's own state. |
| Another account | What that macOS account may reach: its own files, and any of yours that other accounts can read (by default much of your home folder). Listed once you admit the account in **Settings… → Messages → Accounts…**. |

| Network | What the pane's programs get |
|---|---|
| Open | Your network, as you. |
| Only these providers | Only the hosts and ports that the agents you choose name in their manifests, through a proxy nerd runs for that pane alone. For pi, **Choose providers…** narrows that to some of its providers. The agent must honour `HTTPS_PROXY`; one that does not gets no network. Agents whose manifests name different ports cannot share a pane. |
| None | No internet of its own and no name lookups. Services on this Mac (`localhost`) stay reachable, and whatever they pass on: `ssh localhost` when Remote Login is on, a proxy you run here. |

The hosts in the agents' `plugin.json` are a starting point: check them against what your agent contacts. pi's names every provider pi ships with, except four you add yourself if you use them: Bedrock outside us-east-1 and eu-central-1, Vertex and Azure use addresses of your own account; Cloudflare (`api.cloudflare.com`, `gateway.ai.cloudflare.com`) can fetch any URL for an account token, so it would make the pane's network open. In a pane set to Only these providers, Bedrock works with keys, not with SSO or profile login. The proxy checks the name a program asks it to connect to, not the name inside the encrypted connection, so a service behind the same address as an allowed host (a shared CDN) is reached too.

**Choose providers…** appears under the chips once pi is chosen and lists pi's providers, each with the hosts it opens: `deepseek` opens `api.deepseek.com`, `openai` opens `api.openai.com` and `auth.openai.com`, `github-copilot` opens GitHub's Copilot hosts, `api.github.com` and `github.com`, which pi also downloads its tools from. **all** is every provider, those added in a later version of pi included; a list of providers stays that list, so a provider added later stays closed. The pane is saved as `pi/deepseek`, one entry per provider; a pane saved before this choice existed is saved as `pi` and keeps every provider. A provider that a later nerd renames or removes stops the pane rather than opening more: it does not start, and the notice names the pane and the provider; the **Isolation** window shows it as no longer in pi's manifest and drops it on save. Only built-in agents name providers; a plugin's or your own agent manifest names its hosts as one list.

A pane's `~/.pi/agent/*.lock` is writable from every This-folder-only pane: one session can hold another pi session's lock, which only delays that session until the lock is deleted. Likewise a pane can hold `~/.gemini/projects.json.lock`, which makes Gemini outside it wait before it starts, for as long as the pane keeps that lock.

**This folder only** also keeps one session from planting code or instructions for another where agents and tools look for them in your home folder and its known caches, except the agents' session folders. Its `TMPDIR` is a folder only that pane uses (`nm<number>` in your temp folder), removed when its program ends. The shared temp folders (`/private/tmp`, `/private/var/folders`) stay writable, for programs that write there directly, and are shared by every session and tool: what one session leaves there, another can read. Inside the places it may write, these stay read-only: shell, git and editor startup files, `~/.local/bin` and the other folders in your home folder that tools put programs in (`~/.cargo/bin`, `~/go/bin`, `~/.bun/bin`, `~/.deno/bin`, `~/.volta/bin`, `~/.nvm`, and the `shims` of pyenv, rbenv and asdf; your `PATH` itself is not read, so a folder on it that is none of these and lies where the pane may write, in its folder, the temp folders or `~/Library/Caches`, stays writable), the programs `~/.local/bin` links to in `~/.local/share/claude` and `~/.local/share/uv` and Python's user packages in `~/.local/lib` and `~/Library/Python`, the settings and memory of the agents nerd knows, Claude Code's task list, Codex's shared databases, Qwen Code's workflow scripts, what agents source or run later from their own folders, apps in `~/Applications`, Homebrew's settings (`~/.homebrew`, `~/.config/homebrew`), Cargo's and rustup's settings in your home folder and `~/.local` (`.cargo/config.toml`, `rust-toolchain.toml`, a `Cargo.toml` workspace), `go.work`, `package.json` and Claude Code's `CLAUDE.md`, `CLAUDE.local.md` and `AGENTS.md` in your home folder, their own files in `~/.cargo` and `~/.rustup` (the `env` files shells source, Cargo's credentials and downloaded sources, rustup's settings and toolchains), and the known caches whose contents run later (pnpm, uv, deno, Go, Playwright, Poetry, Yarn, node-gyp, pip, Cypress, SwiftPM, Copilot, the system Python's bytecode, Homebrew's downloads, ccache, sccache, esbuild, Bazelisk, Coursier); another cache under `~/Library/Caches` stays writable, and so do Cargo's and rustup's settings, `go.work`, `package.json` and Claude Code's instruction files in a folder between your home folder and a project, such as `~/dev`, to a pane whose folder holds it, and their own files where `CARGO_HOME` or `RUSTUP_HOME` puts them outside `~/.cargo` and `~/.rustup`. A program a `~/.local/bin` link leads to in any other folder stays writable to a pane whose folder holds it. Seatbelt sees a folder moved in whole as one being made, so a missing `~/.<agent>/projects` folder, or a project folder in it an agent has not made yet, can still be put in place with memory or Qwen Code's workflow scripts inside. When the pane's folder is your home folder, its dot files, `~/Library` and `~/bin` stay read-only too, except `~/Library/Caches` and the agents' session folders; choose a project folder for a real limit. The **Isolation** window lists what stops working and warns that what the pane writes in its own folder can run later outside it.

Codex and Gemini in a This-folder-only pane: Codex's databases in `~/.codex` (its list of sessions, goals, memories, logs and queued prompts), which its other sessions read, stay read-only, so Codex there opens databases of its own in the pane's temp folder (`CODEX_SQLITE_HOME`), which go when its program ends. Its session is still recorded in `~/.codex/sessions`; as the **Isolation** window says, it cannot be resumed later. A `sqlite_home` set in `~/.codex/config.toml` overrides nerd's, and Codex then does not start in such a pane. Gemini claims a folder in `~/.gemini/history` for each folder it runs in, and runs git there for its checkpoints, so a pane may not write there: nerd makes that folder and its owner file for the pane's folder before the pane's program starts. It does so for every This-folder-only pane while `~/.gemini` exists, Gemini started or not, because Gemini is usually started later from the pane's shell. Gemini started in a folder below the pane's folder stops there: start it in the pane's folder, or open the pane in that folder. Gemini's checkpointing does not work in such a pane, and its question whether to trust a folder cannot be saved there, so Gemini exits on it: answer it once outside an isolated pane.

A pane that can write its folder can write the repository's `.git` too. nerd's own git there (the file tree's marks, diffs and review, **New worktree…** and **Delete worktree checkout…**) runs none of the repository's own hooks, filters, fsmonitor or lazy fetch; your global git config, such as Git LFS, still applies. A worktree made from the menu is therefore checked out without the repository's post-checkout hook or its local filters, and the notice names the filters left out (Git LFS installed with `--local`, for example). nerd refuses to make or delete a worktree from the menu when the repository's own config includes other files (`include.path`, `includeIf`), since what they make git run in another checkout cannot be checked first. Your own `git` in that folder runs all of it as usual, and whatever the pane wrote in its own folder runs with the access of whoever works there next (your terminal, an agent you start there, a pane set to Everything): the repository's `.git/config` and hooks, an agent's project settings (`.claude/settings.json`, `.mcp.json`, `.codex/config.toml`, `.gemini/settings.json`), a Makefile, a package script. A program `.git/config` names as fsmonitor or as a filter's clean step can run at the next `git status` or `git diff` there, including the one an agent runs as it starts or a git-aware shell prompt runs before each prompt, and one named as a diff's external or textconv program at the next `git diff`; a hook can run as early as the next `git status` (post-index-change, when git rewrites the index), the others at the next commit, checkout, merge or push. Instructions a later agent reads there are the pane's to write too: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, an agent's commands and skills. Review what changed in that folder before you work there outside the pane. nerd reads the repository's config just before its git does, so a pane that swaps the repository's config files in between can still, at the right moment, have a filter of its own run. A git older than 2.31 cannot be told to leave the filters off: with it, nerd shows no marks, diffs or review, refuses **New worktree…** and **Delete worktree checkout…**, and `daemon.log` says why.

Local sockets: with Network **Open**, a This-folder-only pane reaches the Unix sockets in its own temp folder, nerd's message socket, macOS's name lookups (`/private/var/run/mDNSResponder`) and `syslog`, and those in its own folder when that folder holds neither your home folder nor a temp folder (`/private/tmp`, `/private/var/folders`); a pane whose folder is `/`, `/Users`, your home folder or a temp folder gets no socket below it. Every other socket is refused: an ssh agent and Docker, colima, OrbStack, Rancher Desktop, lima or podman, so `git` over ssh and `docker` do not work there, and gpg-agent, git's credential cache, a database listening in `/tmp`, an editor's server, tmux, screen, WezTerm, Zellij, iTerm2 and kitty outside the pane, and Codex's shared background server and its remote control; the ones nerd knows of stay refused even inside the pane's own folder. A socket a program makes in the shared temp folders is refused too, even to the program that made it: one that follows `TMPDIR`, such as Python's multiprocessing, works; one that puts its socket in `/tmp` directly does not. No other system socket is allowed: `git` over https, `curl`, `cargo`, `npm`, `pip` and Homebrew were checked to work without one. So that another program's socket cannot be carried within reach, the pane cannot move or delete a socket outside its own folders, nor move or delete a folder right in `/private/tmp` or the shared temp folder. macOS's `mktemp -d` makes its folder in the shared temp folder whatever `TMPDIR` says, so a folder named as a bare `mktemp -d` names it (`tmp.` and ten letters or digits) may be removed and moved there; a pane cannot give another program's folder that name, but a program that keeps its own socket in such a folder leaves it open to the pane. Any other folder the pane makes right in those folders, one from `mktemp -d -t name` or a `/tmp/…` template included, stays, emptied, until macOS clears it: `rm -rf` of it removes what is inside and then fails. Homebrew's temp files go to the pane's own temp folder. Two ways remain: a folder lower down in the temp folders, or in `~/Library/Caches` or `/private/var/folders` outside the temp folder, that holds another program's socket can be moved whole into the pane's folders and that socket reached. Refusing those moves too would break more tools: package managers rename their folders in `~/Library/Caches`, and tools that ignore `TMPDIR` clean up their folders lower down. Whatever its network, a This-folder-only pane cannot write where tmux, screen, WezTerm, Zellij, iTerm2 and kitty outside it keep their sockets (tmux's and Zellij's own folders, screen's, WezTerm's and iTerm2's, and kitty's where `KITTY_LISTEN_ON` names a file), nor where Codex keeps its shared background server and remote control (`/private/tmp/codex-daemon-<uid>`, `codex-rc-…` in the temp folders, `~/.codex/app-server-control`), so it cannot leave a socket there for them to trust. With **Only these providers** or **None**, a pane reaches no Unix socket but nerd's message socket. With Network **Open**, tmux and Zellij inside the pane work and keep sessions of that pane's running program, which tmux outside nerd and other panes neither see nor change; when the program restarts or the pane closes, its temp folder goes with their sockets, so detached sessions keep running but nothing can reach them. macOS's own `screen` starts no session under any Seatbelt profile, so it does not run in a pane with This folder only, Only these providers or None. A `TMPDIR`, `TMUX_TMPDIR`, `ZELLIJ_SOCKET_DIR` or `SCREENDIR` set in a shell startup file replaces nerd's, and a socket there is refused unless it is in the pane's folder: tmux there then fails. Still reachable with Network Open: services on `localhost` over TCP, such as iTerm2's websocket, kitty listening on `tcp:` and editors' and development servers; a pane with Files Everything can write a This-folder-only pane's temp folder, as it can that pane's own folder.

A pane with This folder only, Only these providers or None cannot ask macOS to start a program for it: `open`, `osascript -e 'tell application …'`, `launchctl` and `defaults write` are refused, and so are lookups of the services that run Automator workflows, shortcuts and user scripts (checked by hand for user scripts; Automator workflows and shortcuts are not yet), so links and files do not open from there, AppleScript cannot control other apps, new launchd jobs are refused, and programs cannot save macOS preferences (`defaults`, Xcode and other Apple tools). A `terminal-notifier` hook loses what its notification opens. Ctrl+click in nerd still opens links. This does not cover a program that talks to a system service directly over XPC, launchers nerd does not know of, `launchctl kickstart`, which is not yet checked, or a pane that started before an update, until its program restarts.

Programs that need the setuid bit (`ps`, `top`, `sudo`) do not run in a pane with This folder only, Only these providers or None: Seatbelt refuses them under a profile. An agent's own Seatbelt sandbox cannot run there either; the **Isolation** window says how to turn it off for each agent.

A pane set to Another account with Network Open has no Seatbelt profile: setuid programs and an agent's own sandbox work there, and the refusals above do not apply. Network None or Only these providers closes that.

**Another account.** **Settings… → Messages → Accounts…** shows the commands that create the account; nerd never runs them. Its panes ask for your password (sudo) each time they start, and run a copy of nerd that only root can change. Put it in place once, and again after each nerd update:

```sh
sudo install -d -o root -g wheel -m 755 "/Library/Application Support/nerd/bin"
sudo install -o root -g wheel -m 755 <path of the running nerd> "/Library/Application Support/nerd/bin/nerd"
```

Until that copy matches the running nerd, the account's panes refuse to start. The window also shows an optional sudoers line that skips the password; with it, any program running as you can act as that account at any time. Neither way stops a program that already controls your own session.

A pane of the account reaches nerd's message socket through `/tmp/nerd-<uid>/`; its Only these providers proxy logs to that account's own `daemon.log`.
